# OpenAI research and web search

Accounts supports OpenAI and Gemini with separate encrypted credentials for each workspace. Switching providers requires the new provider's key. An empty key on a same-provider update preserves the existing encrypted key. The browser receives provider/model/search metadata, never the saved key. OpenAI requests are restricted to `https://api.openai.com/v1` and authenticate in a header.

The recommended cost-conscious default is `gpt-6-luna`: High reasoning for market research, Low reasoning for ad copy. `gpt-6.1-sol` can be selected for harder research if the project's model access and budget allow it. Model discovery is an access check and does not certify generation quota or report accuracy. Sources: [Luna](https://developers.openai.com/api/docs/models/gpt-6-luna), [Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [web search](https://developers.openai.com/api/docs/guides/tools-web-search).

Research first collects a bounded, dated evidence digest with native Responses API web search. A separate High-reasoning request produces the application's strict JSON report from that digest, the original brief, supplied evidence, previous report and follow-up question. Both requests use the selected model. Provider responses are not stored by the Responses API (`store:false`). Search operations incur provider charges in addition to input/output and reasoning tokens; account billing and limits apply.

The application validates field lengths, unique and complete candidate-country coverage, recommendation membership and permitted output fields. One same-model repair can fix malformed or incomplete research. Unknown action fields are rejected. Transient overload receives bounded retries; insufficient API credits do not trigger pointless retries or a silent model downgrade. A 220-second overall processing deadline keeps the workflow within the deployed API proxy timeout.

Each new report saves application-owned retrieval metadata: provider, model, thinking effort, retrieval status, source count, completed search calls and observation time. This survives research history, follow-up reports and campaign drafts. The UI shows this status and clickable citations in the findings. Only actual returned citation URLs or supplied evidence URLs are retained; invented URLs are replaced with `ai-provider`. Model-generated claims cannot declare themselves verified. Market conclusions remain Low-confidence hypotheses pending source and buyer validation.

If search is unavailable or returns no usable citation, the report explicitly says so and uses supplied evidence with hypotheses. API authentication, missing credits, malformed model output or persistent failures cannot create an apparently successful sourced report. Existing research and briefs remain saved. Successful retrieval does not mean every candidate market has supporting evidence; the report must identify country-specific gaps. A source's report date and the system's retrieval timestamp are separate concepts.

Bangladesh product research includes actual product costs and existing delivery coverage, COD failures, return losses, comparable offers and customer evidence. International service research distinguishes national ecommerce adoption from demand for custom development, examines alternatives, buyer objections and trust, and proposes interview/qualified-lead validation. No provider is permitted to invent CPC, acquisition forecasts or profit guarantees. Exact financial constraints and advertising approval remain enforced by application code.

Research version creation does not approve it or launch advertising. Review/edit the draft, approve the current decision and then review the separate campaign plan before any paid launch.
